# 9장 프롬프트 — 특허 네트워크 분석: 인용, 협력, 기술 공간

『지식재산분석론』 9장의 프롬프트 3개를 복사해 쓸 수 있게 옮긴 파일이다(실습 데이터셋 ipa-dataset v2.6).

## 쓰는 법

1. "준비"에 적힌 파일을 이 폴더에서 찾아 대화형 AI에 업로드한다. 프로그래밍 환경은 필요 없다.
2. "먼저 보낼 말"이 있으면 복사해 보내고, 답이 준비와 README.md에 적힌 값과 같은지 본다. AI가 파일을 제대로 읽었는지 확인하는 단계다.
3. "프롬프트"를 복사해 같은 대화에 보낸다.

"진행 방법"은 세 가지를 적은 것이다. 외부 서비스가 있어야 하는 프롬프트의 실행 절차, 대화형 AI에서 할 때 알아 둘 점, 실제 자료나 더 큰 규모로 해 볼 때의 선택 절차다. 외부 서비스의 화면과 조건은 바뀌므로 책에는 무엇이 필요한지만 적고 절차는 이 파일에 적었다. 실습 전체의 안내는 최상위 폴더의 SETUP.md에 있다.

준비와 프롬프트는 책에 실린 글과 같다. 책의 프롬프트가 이 폴더의 파일 이름, 열 이름, 연도, 건수로 적혀 있기 때문이다. 책에서 "프롬프트 맨 아래에 붙인다"고 한 표는 이 파일의 프롬프트에 이미 붙여 두었고, 그런 곳은 "책에 더한 것"에 적었다. 책 본문의 표·그림·예제는 예제 데이터(5,400건)의 값이어서 이 폴더의 파일로 얻는 값과 다르다.

## 프롬프트 9.1 — 패밀리 인용 네트워크와 중심성

**실행 환경**: 코드 실행이 되는 대화형 AI(파일 첨부)

**진행 방법**

외부 서비스는 필요 없다. 이 네트워크는 노드가 5천 개가 넘어 중심성 계산에 시간이 든다. 대화형 AI의 코드 실행에는 시간 제한이 있으므로 다음과 같이 한다.

- 매개 중심성은 프롬프트대로 출발 노드 500개 표본으로 근사하게 한다(10초 안팎). 근사한 값이라는 것을 결과 표에 적게 한다.
- 근접·조화 중심성은 프롬프트대로 노드 사이 최단 거리 행렬을 한 번 구해 계산하게 한다(각 5초 안팎). 네트워크 분석 도구의 기본 함수로 계산하면 몇 분이 들어 중간에 멈출 수 있다.
- 한 번에 끝나지 않으면 "들어오는 차수와 연결 성분부터", "다음은 매개 중심성", "다음은 근접·조화 중심성"처럼 지표를 하나씩 나누어 요청한다.
- AI가 네트워크 분석 도구가 없다고 하면 "도구 없이 직접 계산하는 코드를 써서 실행해 줘"라고 요청한다.

**준비**

- ① ch09 폴더의 families.csv(패밀리 마스터. family_id, assignee_std, priority_date, sub_tech, title, n_forward, in_analysis_set 등)를 업로드하고 행 수와 in_analysis_set이 1인 행 수를 묻는다.
- ② 같은 폴더의 citations.csv(문서 단위 인용 77,841행, 여섯 열)를 업로드한다. 프롬프트가 두 열만 남기고 중복 행을 지워 인용 테이블로 쓰게 한다.
- ③ 노드가 5천 개가 넘어 중심성 계산에 시간이 많이 든다. 한 번에 끝나지 않으면 지표를 하나씩 나누어 요청한다.

**먼저 보낼 말**

```text
첨부한 families.csv의 행 수와 in_analysis_set이 1인 행의 수, citations.csv의 행 수를 알려 줘.
```

**프롬프트**

```text
첨부한 families.csv에서 in_analysis_set이 1인 행을 패밀리 마스터로 쓰고, 함께 첨부한 citations.csv에서 citing_family_id(인용하는 쪽)와 cited_family_id(인용되는 쪽) 두 열만 남기고 중복 행을 지워 방향 있는 인용 네트워크를 만들어 줘. 엣지는 인용하는 패밀리에서 인용되는 패밀리로 향하고, 두 패밀리가 모두 마스터에 있는 행만 남겨.
노드 수, 엣지 수, 연결 성분 수, 가장 큰 연결 성분의 노드 수, 들어오는 차수가 n_forward보다 큰 패밀리 수를 먼저 출력해 줘.
들어오는 차수, 매개 중심성(방향을 지우고 정규화. 오래 걸리면 출발 노드 500개 표본, 시드 11로 근사하고 그렇게 적는다), 근접 중심성(가장 큰 연결 성분 안), 조화 중심성(둘은 노드 사이 최단 거리 행렬을 한 번 구해 계산한다)을 계산해 매개 중심성 상위 20건을 family_id, assignee_std, priority_date, sub_tech, n_forward와 함께 보여 주고, 그중 들어오는 차수 상위 20건에는 없는 패밀리를 표시해 줘.
사용한 코드와 라이브러리 버전을 함께 보여 줘.
한 번에 끝내기 어려우면 단계를 나누어 차례로 실행하고, 단계마다 중간 결과를 보여 줘.
```

## 프롬프트 9.2 — 주경로 분석

**실행 환경**: 코드 실행이 되는 대화형 AI(파일 첨부)

**준비**

- ① 프롬프트 9.1을 보낸 대화에 이어 보낸다. 우선일·제목은 families.csv(priority_date, title)에 있다. 새 대화면 프롬프트 9.1의 준비대로 families.csv와 citations.csv를 다시 업로드한다.
- ② ch09 폴더의 candidates.csv(매입 후보 8건. candidate_id, family_id 등)를 업로드한다.

**프롬프트**

```text
프롬프트 9.1의 인용 네트워크(인용하는 → 인용되는)에 가상 출발·도착 노드를 이어 엣지마다 탐색 경로 수(SPC)를 계산해 줘. 경로 수는 매우 커지므로 정수로 정확히 계산하고, 순환이 있으면 우선일이 이른 패밀리에서 늦은 패밀리로 향하는 엣지를 지우고, 지운 엣지의 수와 목록을 보고해 줘.
SPC 합이 가장 큰 전역 주경로와, SPC 상위 10개 엣지에서 앞뒤로 국소 탐색을 이어 간 핵심 경로(key-route) 방식의 주경로를 찾아 줘. 동점인 경로와 엣지는 모두 보여 줘.
경로 위 패밀리를 priority_date 순으로 family_id, assignee_std, sub_tech, title, 이웃 엣지의 SPC 열로 정리하고, 출원인별 건수와 가상 출발·도착 노드의 SPC 합, 사용한 코드와 라이브러리 버전을 함께 보여 줘. 첨부한 candidates.csv의 family_id 8건이 두 주경로 위에 있는지도 표시해 줘.
한 번에 끝내기 어려우면 단계를 나누어 차례로 실행하고, 단계마다 중간 결과를 보여 줘.
```

## 프롬프트 9.3 — 링크 예측의 시간 분할 검증

**실행 환경**: 코드 실행이 되는 대화형 AI(파일 첨부)

**진행 방법**

외부 서비스는 필요 없다.

- 상위 20위에 점수가 같은 쌍이 많다(공통 이웃 수는 정수라 동점이 흔하다). 동점을 어떻게 잘랐는지 AI에게 적게 하고, 정밀도@20이 그 처리에 따라 달라지는지 본다.

**준비**

- ① ch09 폴더의 applicants.csv(5,778행. family_id, assignee_id, assignee_std, assignee_sequence)를 업로드하고 행 수를 묻는다.
- ② 같은 폴더의 families.csv(family_id, priority_date)를 같은 대화에 업로드하고, applicants.csv의 family_id 중 families.csv에 없는 것이 몇 건인지 묻는다.

**먼저 보낼 말**

```text
첨부한 applicants.csv의 행 수와, applicants.csv의 family_id 가운데 families.csv에 없는 것이 몇 건인지 알려 줘.
```

**프롬프트**

```text
첨부한 applicants.csv(family_id, assignee_std, assignee_sequence)와 families.csv의 priority_date로 공동출원 네트워크를 만들어 줘. UNKNOWN은 빼고, 가중치는 함께 낸 패밀리 수야.
2019년까지의 패밀리로 학습 네트워크를, 2020~2022년 패밀리로 학습 네트워크에 없던 새 엣지를 만들고, 두 기간 모두 패밀리가 3건 이상인 출원인만 평가해 줘.
미연결 쌍마다 공통 이웃 수, Jaccard 지수, Adamic/Adar 지수, 선호 연결 점수를 계산해 지수별 정밀도@20과 윌슨 95% 구간, AUC, 무작위 기준선을 한 표로 보여 주고, 사용한 코드와 라이브러리 버전도 보여 줘.
한 번에 끝내기 어려우면 단계를 나누어 차례로 실행하고, 단계마다 중간 결과를 보여 줘.
```
