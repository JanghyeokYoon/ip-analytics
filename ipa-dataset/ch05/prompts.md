# 5장 프롬프트 — AI와 함께하는 특허 분석

『지식재산분석론』 5장의 프롬프트 3개를 복사해 쓸 수 있게 옮긴 파일이다(실습 데이터셋 ipa-dataset v2.6).

## 쓰는 법

1. "준비"에 적힌 파일을 이 폴더에서 찾아 대화형 AI에 업로드한다. 프로그래밍 환경은 필요 없다.
2. "먼저 보낼 말"이 있으면 복사해 보내고, 답이 준비와 README.md에 적힌 값과 같은지 본다. AI가 파일을 제대로 읽었는지 확인하는 단계다.
3. "프롬프트"를 복사해 같은 대화에 보낸다.

"진행 방법"은 세 가지를 적은 것이다. 외부 서비스가 있어야 하는 프롬프트의 실행 절차, 대화형 AI에서 할 때 알아 둘 점, 실제 자료나 더 큰 규모로 해 볼 때의 선택 절차다. 외부 서비스의 화면과 조건은 바뀌므로 책에는 무엇이 필요한지만 적고 절차는 이 파일에 적었다. 실습 전체의 안내는 최상위 폴더의 SETUP.md에 있다.

준비와 프롬프트는 책에 실린 글과 같다. 책의 프롬프트가 이 폴더의 파일 이름, 열 이름, 연도, 건수로 적혀 있기 때문이다. 책에서 "프롬프트 맨 아래에 붙인다"고 한 표는 이 파일의 프롬프트에 이미 붙여 두었고, 그런 곳은 "책에 더한 것"에 적었다. 책 본문의 표·그림·예제는 예제 데이터(5,400건)의 값이어서 이 폴더의 파일로 얻는 값과 다르다.

## 프롬프트 5.1 — 세부 기술 1차 분류

**실행 환경**: 웹 대화형 AI만으로 가능(300행을 한 번에 읽지 못하면 50행씩 나누어 보낸다)

**진행 방법**

외부 서비스는 필요 없다. 이 분류는 AI가 초록을 직접 읽고 판정하는 일이다.

- AI가 키워드 규칙이나 분류 코드를 만들어 한꺼번에 분류하려 하면 "코드로 분류하지 말고 한 건씩 초록을 읽고 판정해 줘"라고 다시 지시한다.
- 정의에서 T1(치환 조성)과 T4(황화수소 억제·수분 안정화 처리)는 경계가 가깝다. 수분에 안정한 황화물 전해질처럼 두 정의에 모두 해당하는 초록에서 판정이 어긋나기 쉽다. 이 경계는 5장 소과제 2에서 기준 문장을 고치는 대상이다.

**준비**

- ① 실습 데이터셋(ipa-dataset) ch05 폴더의 subtech_definitions.csv(T1~T7·X 정의. 열: code, name, definition, include, exclude, example_family_ids)와 subtech_examples.csv(예시 패밀리의 초록. code, family_id, title, abstract)를 업로드하고 코드별 정의를 한 줄로 요약하게 한다.
- ② classify_input.csv(초록 300건: family_id, title, abstract, cpc)를 업로드하고 프롬프트를 보낸다. 본문 예제의 4,800건과 달리 실습 파일은 300건이고 청구항 1(first_claim) 열이 없어 초록으로 판정한다.
- ③ AI가 300행을 한 번에 읽지 못하면 50행씩 여섯 파일로 나누어 차례로 보내고 프롬프트의 300을 50으로 고친다.

**먼저 보낼 말**

```text
첨부한 subtech_definitions.csv의 코드(T1~T7, X)별 정의를 한 줄씩 요약해 줘.
```

**프롬프트**

```text
다음 5년 기술 로드맵에 쓸 세부 기술별 규모와 성장 추이를 계산하려고 패밀리마다 세부 기술 하나를 붙인다. 같은 기준을 분기마다 새로 공개되는 특허에 다시 적용한다.
첨부한 classify_input.csv는 300행이고 한 행은 패밀리 하나(대표 문서)다. 열은 family_id, title, abstract, cpc이며 텍스트는 영문이다.
첨부한 subtech_definitions.csv의 T1~T7 정의와 subtech_examples.csv의 예시만을 기준으로 삼고 새 범주를 만들지 마. 어느 정의에도 맞지 않으면 X로 둬. 한 패밀리에 코드 하나만 배정하고, 두 코드 모두에 해당하면 초록의 주된 대상으로 정해 줘. 한 건씩 초록을 읽고 판정하며, CPC 코드나 키워드만으로 판정하지 마.
결과는 family_id, sub_tech, reason(판정 근거 한 문장, 초록의 구절을 인용), confidence(높음·중간·낮음)의 네 열 CSV로 돌려 줘.
처리한 행 수와 sub_tech별 건수, 그 합을 출력하고, 합이 300이 아니면 멈추고 알려 줘.
```

## 프롬프트 5.2 — 분류를 묶음으로 나누어 실행하기

**실행 환경**: 코드 실행이 되는 대화형 AI(파일 첨부)

**진행 방법**

책의 프롬프트는 대화형 AI에서 50건씩 묶어 실행한다. 외부 서비스는 필요 없다.

- 300건의 초록은 분량이 많다(묶음 하나가 책 스무 쪽쯤이다). 묶음 하나를 끝낼 때마다 결과를 CSV로 저장하게 하고, 대화가 길어져 AI가 앞의 지시를 놓치면 새 대화를 열어 정의 파일과 프롬프트 5.1의 지시, 남은 묶음을 다시 보낸다.
- AI가 코드로 키워드 규칙을 만들어 분류하려 하면 "한 건씩 초록을 읽고 판정해 줘"라고 다시 지시한다.
- 묶음마다 결과 행 수가 50인지 확인한 뒤 다음 묶음을 진행시킨다.

아래는 수천 건을 API로 자동화할 때의 선택 절차다.

1. API는 대화형 서비스와 따로 가입하고 요금을 내는 경우가 많다. 최상위 폴더 SETUP.md의 4절대로 Python을 준비하고 5절대로 API 키를 발급받아 환경 변수에 넣는다.
2. 대화형 AI에게 "프롬프트 5.2의 일을 API로 실행하는 Python 코드를 써 줘. 50건씩 묶어 보내고, temperature는 0으로 고정하고, 답은 family_id, sub_tech, reason, confidence 네 키의 JSON으로 받고, API 키는 환경 변수에서 읽어 줘"라고 요청해 코드를 받는다.
3. 받은 코드의 모델 이름과 환경 변수 이름이 자기가 쓰는 서비스와 맞는지 본다.
4. 한 묶음만 먼저 실행해 결과의 네 키와 사용량·비용을 확인한 뒤 전체를 실행한다. 실패한 묶음 번호가 기록되는지 본다.

이 절차는 2026년 11월에 확인한 것이다. 화면 이름, 한도, 요금은 바뀔 수 있으니 다르면 서비스의 공식 안내를 따른다.

**준비**

- ① ch05 폴더의 classify_input.csv, subtech_definitions.csv, subtech_examples.csv를 업로드한다(프롬프트 5.1을 보낸 대화면 생략).
- ② 프롬프트 5.1을 보낸 대화에 이어서 보낸다. 새 대화라면 프롬프트 5.1의 지시문을 아래에 붙인다.
- ③ 첫 묶음의 결과에서 네 열을 확인한 뒤 나머지를 진행시킨다. 수천 건을 API로 자동화하는 방법은 ch05 폴더 prompts.md에 있다.

**먼저 보낼 말**

```text
첨부한 classify_input.csv의 행 수와 열 이름을 알려 줘.
```

**프롬프트**

```text
프롬프트 5.1의 분류를 첨부한 classify_input.csv(열: family_id, title, abstract, cpc) 300건 전체에 실행해 줘. 기준은 subtech_definitions.csv·subtech_examples.csv(세부 기술 정의와 예시)이고, 묶음마다 프롬프트 5.1의 지시와 정의를 다시 확인해 줘.
50건씩 묶음으로 나누어 차례로 처리하되 한 묶음을 한 번에 읽기 어려우면 묶음을 더 작게 나누고, 결과 행마다 묶음 번호(batch)를 붙여 한 CSV 파일에 모아 줘. 답은 family_id, sub_tech, reason, confidence 네 열로 적어 줘.
오류가 난 묶음은 그 묶음의 기존 결과 행을 모두 지운 뒤 다시 실행하고, 다시 실행한 묶음 번호를 기록해 줘.
끝나면 입력 행 수, 결과 행 수, 두 번 이상 나온 family_id 수, sub_tech별 건수를 출력해 줘.
```

## 프롬프트 5.3 — 평가 표본의 구간과 보정 건수

**실행 환경**: 코드 실행이 되는 대화형 AI(파일 첨부)

**진행 방법**

외부 서비스는 필요 없다.

- 준비의 두 표(평가 표본 100행, sub_tech별 AI 건수)는 프롬프트 5.2를 보낸 대화에서 AI에게 만들게 한다. 새 대화에서 할 때는 두 표를 CSV 파일로 저장해 두었다가 업로드한다.
- rater_a와 rater_b가 다른 건은 3건이다. 어느 값을 기준으로 삼을지 정해 AI에게 알려 준다.
- 윌슨 구간을 계산하는 통계 도구가 없다고 하면 "식으로 직접 계산해 줘"라고 요청한다.
- 이 표본에는 5건 미만인 범주가 없을 수 있다. 그때는 표시가 없는 것이 맞다.

**준비**

- ① 프롬프트 5.2를 보낸 대화에 ch05 폴더의 eval_sample.csv(사람 판정 100건. 열: family_id, rater_a(100건), rater_b(30건), 값은 T1~T7·X)를 업로드해 300건의 분류 결과(sub_tech)를 family_id로 붙이게 한다. human_label(rater_a 값, rater_b와 다르면 협의한 값)과 ai_label 열의 100행 표가 된다.
- ② 300건 결과의 sub_tech별 건수 표(sub_tech, ai_count)도 만들게 하고, data_dictionary.csv를 업로드해 행 수(100)와 라벨 값(T1~T7·X)을 물은 뒤 프롬프트를 보낸다.

**먼저 보낼 말**

```text
방금 만든 평가 표본 표의 행 수와 human_label·ai_label에 나오는 값의 목록을 알려 줘.
```

**프롬프트**

```text
준비에서 만든 평가 표본 100행(열: family_id, human_label, ai_label, 값은 T1~T7 또는 X)과 sub_tech별 AI 건수(300건 전체)로 분류 품질과 보정 건수를 계산하려 한다.
① 여덟 범주 전체 불일치율의 윌슨 95% 구간, ② 세부 기술별 정밀도·재현율과 각각의 윌슨 95% 구간, ③ 보정 건수(AI 건수 × 정밀도 ÷ 재현율)와 그 범위(정밀도 하한 ÷ 재현율 상한부터 정밀도 상한 ÷ 재현율 하한까지)를 한 표로 만들어 줘.
윌슨 구간은 통계 라이브러리의 함수(예: statsmodels의 proportion_confint, method='wilson')로 계산하고, 표본에 5건 미만인 범주는 표시해 줘.
비교를 위해 표본을 2,000번 복원 추출한 부트스트랩 95% 구간도 보정 건수에 대해 계산해 줘.
```
