# 부록 A 프롬프트 — 미국 특허 데이터베이스의 구조

『지식재산분석론』 부록 A의 프롬프트 2개를 복사해 쓸 수 있게 옮긴 파일이다(실습 데이터셋 ipa-dataset v2.6).

## 쓰는 법

1. "준비"에 적힌 파일을 이 폴더에서 찾아 대화형 AI에 업로드한다. 프로그래밍 환경은 필요 없다.
2. "먼저 보낼 말"이 있으면 복사해 보내고, 답이 준비와 README.md에 적힌 값과 같은지 본다. AI가 파일을 제대로 읽었는지 확인하는 단계다.
3. "프롬프트"를 복사해 같은 대화에 보낸다.

"진행 방법"은 세 가지를 적은 것이다. 외부 서비스가 있어야 하는 프롬프트의 실행 절차, 대화형 AI에서 할 때 알아 둘 점, 실제 자료나 더 큰 규모로 해 볼 때의 선택 절차다. 외부 서비스의 화면과 조건은 바뀌므로 책에는 무엇이 필요한지만 적고 절차는 이 파일에 적었다. 실습 전체의 안내는 최상위 폴더의 SETUP.md에 있다.

준비와 프롬프트는 책에 실린 글과 같다. 책의 프롬프트가 이 폴더의 파일 이름, 열 이름, 연도, 건수로 적혀 있기 때문이다. 책에서 "프롬프트 맨 아래에 붙인다"고 한 표는 이 파일의 프롬프트에 이미 붙여 두었고, 그런 곳은 "책에 더한 것"에 적었다. 책 본문의 표·그림·예제는 예제 데이터(5,400건)의 값이어서 이 폴더의 파일로 얻는 값과 다르다.

## 프롬프트 A.1 — 필요한 테이블과 결합 키 정리

**실행 환경**: 웹 대화형 AI만으로 가능

**진행 방법**

이 프롬프트는 미국 특허상표청이 제공하는 PatentsView 대량 자료의 데이터 사전을 쓴다. 실습 데이터셋 파일은 필요 없다.

1. PatentsView 자료는 2026년 3월 20일부터 미국 특허상표청의 Open Data Portal로 옮겨 제공한다고 공지되었다(공지 2026-03-18). 대량 자료 목록은 https://data.uspto.gov/bulkdata/datasets 에 있고, 옮긴 뒤의 안내는 https://data.uspto.gov/support/transition-guidance/patentsview 에 있다.
2. 대량 자료 목록에서 PatentsView의 등록 특허(granted patents, 테이블 이름이 g_로 시작)와 공개 출원(pre-grant publications, pg_로 시작) 자료를 찾는다.
3. 데이터 사전(data dictionary) 파일을 다운로드한다. 파일이 없고 화면에 표로만 나오면 표를 복사해 텍스트 파일로 저장한다. 다운로드에 계정 로그인이나 API 키가 필요하면 포털의 안내를 따른다.
4. 데이터 사전을 업로드하고 테이블 수와 g_patent의 열 이름을 물어 AI가 사전을 읽었는지 확인한 뒤 프롬프트를 보낸다.

데이터 사전을 구하지 못했을 때: 프롬프트의 첫 줄을 "네가 아는 PatentsView의 테이블 구조로 정리하고, 기억에 의존한 테이블과 열은 따로 표시해 줘"로 바꾸어 보낸 뒤, 답을 책의 표 A.4와 대조한다. 실제 자료를 받기 전에 반드시 데이터 사전으로 다시 확인한다.

PatentsView의 검색·API·시각화 기능은 옮기는 동안 잠시 멈춘다고 공지되었다. 최근 소식은 미국 특허상표청의 PatentsView 안내 페이지(https://www.uspto.gov/ip-policy/economic-research/patentsview)에서 확인한다. 이 절차는 2026년 11월에 확인한 것이다. 화면 이름, 한도, 요금은 바뀔 수 있으니 다르면 서비스의 공식 안내를 따른다.

**준비**

- ① 실습 데이터셋 파일은 필요 없다. PatentsView 대량 자료의 등록 특허(g_)와 공개 출원(pg_) 데이터 사전(테이블 이름, 열 이름과 정의)을 다운로드하거나 화면의 표를 텍스트 파일로 저장해 업로드한다(받는 곳과 절차는 appA 폴더 prompts.md).
- ② 테이블 수와 g_patent의 열 이름을 물어 AI가 사전을 읽었는지 확인한다.

**먼저 보낼 말**

```text
첨부한 데이터 사전의 테이블 수와 g_patent 테이블의 열 이름을 알려 줘.
```

**프롬프트**

```text
미국 특허 데이터로 전고체 전지 분야의 출원인별·연도별 등록 특허 수와 피인용 수를 계산하려 한다. 첨부한 것은 PatentsView 등록 특허·공개 출원 자료의 데이터 사전이다.
이 계산에 필요한 테이블과 열, 테이블을 잇는 키, 각 테이블에서 한 행이 뜻하는 것, 테이블 사이의 관계(1:1, 1:N, N:1, N:M)를 표로 정리해 줘. 피인용 수에는 등록 특허가 받은 인용과 공개 출원이 받은 인용을 모두 넣고, 각각 어느 테이블의 어느 열에서 찾는지 적어 줘.
결합했을 때 행이 늘어나거나 사라질 수 있는 곳을 표시하고, 그 경우 왼쪽 결합과 고유 번호 집계로 중복 없이 산출하는 방법도 적어 줘. 아직 코드는 쓰지 마. 데이터 사전에 없는 열 이름을 추측해서 쓰지 말고, 확실하지 않은 것은 표시해 줘.
```

## 프롬프트 A.2 — 분석용 데이터셋 조립과 검증(4단계)

**실행 환경**: 코드를 받아 대량 자료가 있는 PC에서 실행(외부 자료 필요. 절차는 appA 폴더 prompts.md)

**진행 방법**

이 프롬프트는 대화형으로 바꿀 수 없다. 받은 코드를 실제 대량 자료 파일이 있는 PC에서 실행해야 한다. 실습 번호는 가상 번호이므로 자기 번호 목록으로 실행한다. 코드를 받는 데까지는 대화형 AI로 한다.

**가. 준비**

1. 최상위 폴더 SETUP.md의 4절대로 내 PC에 Python을 준비하고, 명령 창에서 `pip install pandas duckdb`로 패키지를 설치한다.
2. 프롬프트 A.1에서 AI가 정리한 "필요한 테이블" 목록의 파일만 다운로드한다(받는 곳은 프롬프트 A.1의 진행 방법). 파일 하나가 수백 MB에서 수 GB이므로 저장 공간을 수십 GB 비워 둔다.
3. 다운로드한 파일을 한 폴더에 모으고, 번호 목록 CSV(pub_number, kind 열)도 같은 폴더에 둔다.

**나. 코드 받기**

4. 파일마다 머리글과 첫 5행을 뽑아 텍스트로 저장한다. 대화형 AI에게 "이 파일의 머리글과 첫 5행을 출력하는 코드를 써 줘"라고 요청해 받은 코드를 실행하면 된다. 대량 자료는 탭으로 구분한 텍스트를 압축한 파일로 제공되어 왔다. 형식이 다르면 파일 이름과 형식을 AI에게 알려 준다.
5. 번호 목록 CSV, 데이터 사전, 머리글·첫 5행을 대화형 AI에 업로드하고 프롬프트를 보낸다. 전체 파일은 업로드하지 않는다.

**다. 실행과 확인**

6. 받은 코드를 파일을 둔 폴더에 .py 파일로 저장하고, 명령 창에서 그 폴더로 이동해 `python 파일이름.py`로 실행한다.
7. 코드가 큰 파일을 통째로 읽지 않고 번호 목록에 있는 행만 추리는지 확인한다. 메모리가 모자라다는 오류가 나면 오류 메시지를 AI에게 보내 나누어 읽게 고친다.
8. 단계마다 문서 파일의 행 수, grant_date가 빈 행의 종류 코드, family_id가 빈 행을 본다. 어긋나면 그 단계의 출력과 함께 AI에게 보낸다.
9. 완성한 데이터셋의 행 수와 열 이름을 책 7장의 데이터 사전과 대조한다.

**라. 실제 자료 없이 연습하기**

10. 실제 대량 자료를 받지 않아도 조립 단계는 연습할 수 있다. 실습 데이터셋 ch07 폴더의 원자료 파일(docs_raw, family_docs_raw, priority_raw, maintenance_raw, file_wrapper_raw)이 대량 자료에서 추린 결과와 같은 모양이다. 7장의 프롬프트 7.2(패밀리 통합)와 7.3(인용·유지료·파일 래퍼 결합)을 그 파일로 실행하면 이 프롬프트의 3~4단계와 같은 일을 하게 된다.
11. 처음 실행할 때는 번호 목록을 10건으로 줄여 코드가 끝까지 도는지 확인한 뒤 전체 목록으로 실행한다.

이 절차는 2026년 11월에 확인한 것이다. 화면 이름, 한도, 요금은 바뀔 수 있으니 다르면 서비스의 공식 안내를 따른다.

**준비**

- ① 번호 목록 CSV(pub_number, kind 열), 프롬프트 A.1의 데이터 사전, 쓸 파일 각각의 머리글·첫 5행을 업로드한다.
- ② AI에게 번호 목록의 행 수를 물어 적어 둔다(본문 예제는 12,300행).

**먼저 보낼 말**

```text
첨부한 번호 목록의 행 수를 알려 줘.
```

**프롬프트**

```text
첨부한 것은 검색식으로 확정한 문서 번호 목록(열: pub_number, kind), PatentsView 데이터 사전, 그리고 쓸 파일 각각의 첫 5행이다. 전체 파일은 첨부하지 않으며 코드는 내 PC의 Python에서 실행한다. 아래 네 단계의 코드를 한 단계씩 써 주고, 각 단계의 출력(결합 전후 행 수, 키 일치율, 열별 빈 값 수의 표)을 내가 다시 첨부하기 전에는 다음 단계로 가지 마.
1단계 — 번호 통일과 문서 본체: 번호 형식은 통일하되 원래 번호는 남기고 바꾼 번호를 새 열로 둬(출원번호·특허 번호는 숫자와 접두어만, Google 공개번호는 "US-번호-종류" 형식, 공개 출원은 일련번호 앞자리 0 제거). 번호 목록을 왼쪽에 두고 g_patent, g_application, g_patent_abstract, pg_published_application, pg_granted_pgpubs_crosswalk를 왼쪽 결합해 문서 파일을 만들어 줘. 대용량 파일은 통째로 읽지 말고 나누어 읽거나 DuckDB로 번호부터 걸러 줘.
2단계 — 긴 형식 테이블: 출원인(g_assignee_not_disambiguated, g_assignee_disambiguated, 공개 출원의 출원인), 분류(g_cpc_current), 발명자(g_inventor_disambiguated), 청구항(연도별 청구항 파일, 공개 출원 청구항 파일)을 번호로 걸러 문서 번호를 키로 하는 긴 형식 테이블로 만들어 줘.
3단계 — 인용과 패밀리: 전방 인용은 g_us_patent_citation과 g_us_application_citation 전체에서 찾고, Google 공개 데이터셋에서 받은 publication_number·family_id·country_code 파일로 문서–family_id 대응표를 만들되 인용한 문서의 family_id도 넣어 줘.
4단계 — 법적 상태 자료: 유지료 사건 파일, g_us_term_of_grant, g_foreign_priority, g_us_rel_doc, g_pct_data, 파일 래퍼 사건 기록(비최종·최종 거절통지와 포기 사건만), 거절이유 자료, 양도 데이터셋을 번호로 걸러 줘. 존속기간 자료에는 가장 이른 미국 정규 출원일(PCT 국내단계는 국제출원일), 조정 일수, 존속기간 포기 날짜, 만료일(그 출원일 + 20년 + 조정 일수, 포기일이 더 이르면 그 날)을 넣어 줘.
패밀리 단위로 올리는 작업과 legal_status 판정은 하지 마. 사용한 자료의 판(끝 날짜와 다운로드한 날), 코드, 라이브러리 버전을 함께 적어 줘.
```
